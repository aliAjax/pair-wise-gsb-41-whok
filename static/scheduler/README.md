# 台风查勘排程台（零依赖 · 纯前端）

面向台风灾后乡镇查勘的排程工具：案件按 **事件 → 区域 → 损失** 排序，人员登记班次与高风险资质；
派工自动校验任务撞车、跨区赶场间隔和资质，校验不过的案件**留在待派区并写明原因**；
到场记录灾损与现场风险，**高风险案件复核确认前冻结预付**；改派/取消立即释放班次；
案件重开后仍可追溯任务、人员与全部变更。

## 三层分离（互不越界）

| 文件 | 层 | 职责 |
| --- | --- | --- |
| `js/storage.js` | 保存层 | localStorage 读写、演示数据初始化（`Store.load/save/reset`），不含业务规则 |
| `js/scheduler.js` | 排程层 | 纯函数规则：排序、派工校验、复核人校验、预付门槛、班次占用；不碰 DOM 和存储 |
| `js/app.js` | 页面层 | 渲染、弹窗、交互；规则调 `Scheduler`，持久化调 `Store` |
| `index.html` / `styles.css` | 页面 | 结构与样式 |

全部使用原生 HTML/CSS/JavaScript（经典 `<script>`，非 ES Module），**不加任何第三方依赖、不需要构建**。

## 运行

方式一：直接用浏览器打开 `index.html`（数据存浏览器 localStorage）。

方式二：通过仓库自带的标准库 HTTP 服务：

```bash
python3 app.py
# 浏览器访问 http://127.0.0.1:8207/scheduler/
```

## 业务规则

- **案件排序**：所属事件发生时间新→旧 → 区域固定顺序 → 估损金额高→低。
- **派工校验**（任一不过即留在待派区，红框逐条写明原因，不占用班次）：
  1. 高风险现场须派具备**高风险资质**的查勘员；
  2. 派工时段必须落在该人员已登记的**班次**内；
  3. 与该人员在办任务**时间重叠即撞车**（已取消/已改派任务不参与）；
  4. 与在办任务**跨区域**时，两任务间隔须 **≥ 90 分钟**；同区域不限制。
- **到场记录**：灾损描述、现场估损、现场风险（高风险至少一条）。
- **复核**：复核人须高风险资质且与到场查勘员**不是同一人（回避）**。
- **预付**：高风险案件未经复核确认，预付按钮冻结，提交时再次校验门槛。
- **改派 / 取消**：旧任务立即标记为已改派/已取消并**释放班次**，可马上再排别人；
  改派的新派工若校验失败，原任务与原班次保留。
- **重开**：已取消/已预付的案件可重开回待派区，历史任务、人员、到场/复核/预付与变更日志全部保留，
  在「轨迹」中可完整追溯；「变更日志」页支持按案件、按操作筛选。

## 测试

排程层是纯函数，可用 Node 直接跑零依赖测试：

```bash
node tests/scheduler.test.js
```

覆盖排序、资质/班次/撞车/跨区 90 分钟/释放后再派、多原因并发、复核人资质与回避、预付门槛等 13 个断言。
